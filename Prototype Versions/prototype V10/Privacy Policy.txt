5. LOCAL-FIRST STORAGE ARCHITECTURE & DEVICE-RESIDENT DATA CATEGORIES
========================================================================================================================
5.1. Locality of Storage:
    All user profiles, browser states, cache blocks, indexed records, and configuration preferences reside strictly within your 
    operating system application data path (e.g., `%APPDATA%\nexusweb-v10` on Windows, `~/.config/nexusweb-v10` on Linux, 
    or `~/Library/Application Support/nexusweb-v10` on macOS).

5.2. Encrypted Password & Autofill Vault:
    (a) When a user elects to store credentials in NeXusWeb, the credentials are encrypted using industry-standard Advanced 
        Encryption Standard in Galois/Counter Mode with 256-bit keys (AES-256-GCM).
    (b) Cryptographic key derivation is performed locally utilizing Password-Based Key Derivation Function 2 (PBKDF2) with 
        a minimum iteration count of 600,000 rounds and a cryptographically secure random salt.
    (c) The decryption key resides exclusively in device RAM during an authenticated session and is never written in plaintext 
        to disk or transmitted over any network interface.

5.3. Bookmarks, History & ScratchPad Notes:
    (a) Bookmarks, browsing records, download histories, and developer ScratchPad notes are written to local JSON and SQLite 
        database files on the local filesystem.
    (b) Users possess full administrative autonomy to inspect, copy, backup, or permanently purge these files at any time 
        via built-in browser settings or direct file manager manipulation.

5.4. Cookies, Web Storage & Cache:
    (a) Site cookies, localStorage, sessionStorage, IndexedDB, and WebSQL caches are governed by standard Chromium sandboxing 
        rules and stored locally.
    (b) In "Private Den" (Incognito/Sovereign) mode, all session storage, cookies, and temporary memory blocks are allocated 
        ephemerally in RAM and permanently expunged upon tab or window closure.

5.5. Universal File Viewer & Workspaces:
    Files opened within the Universal File Viewer (including PDFs, Office documents, markdown files, media files, and code buffers) 
    are rendered strictly via local client-side memory buffers. No file contents are uploaded to cloud servers for parsing or conversion.

6. CHEVRONNEXUS SYNC INFRASTRUCTURE (ZERO-KNOWLEDGE END-TO-END ENCRYPTED)
========================================================================================================================
6.1. Optional Activation & Zero-Knowledge Architecture:
    (a) ChevronNexus Sync is entirely optional and remains inactive by default until explicitly enabled by the user.
    (b) The Sync system operates under a strict Zero-Knowledge End-to-End Encrypted (E2EE) cryptographic model.
    (c) All user sync payloads (bookmarks, saved credentials, active tab states, and preferences) are fully encrypted on the 
        originating client device BEFORE transmission over the network.

6.2. Cryptographic Key Derivation & Recovery Phrase:
    (a) The encryption keys are derived client-side from the user's Master Password and an optional 12-word BIP39 mnemonic seed phrase.
    (b) The Master Password and recovery seed are NEVER transmitted to or stored on Chevron Nexus servers in plaintext or hash 
        form that permits decryption.
    (c) Chevron Nexus engineers, system administrators, and automated backend processes have ZERO technical capacity to decrypt, 
        inspect, or reconstruct user sync payloads.

6.3. Server-Side Storage & Lifecycle:
    (a) The Sync server stores only opaque, encrypted binary blobs associated with an anonymized cryptographic account identifier.
    (b) Encrypted payloads stored on the Sync server are retained strictly to facilitate multi-device synchronization and are 
        subject to automated deletion after 180 consecutive days of account inactivity.
    (c) Users may purge their entire cloud sync dataset and delete their account at any time directly through the Sync Management panel.

6.4. Hosting Infrastructure & Data Residency:
    All ChevronNexus Sync relay and storage nodes are hosted within enterprise data centers located in Mumbai, Maharashtra, India 
    (AWS ap-south-1 region), adhering strictly to Indian data sovereignty standards.

7. CHEVRONNEXUS HOME (PRO) LOCAL AREA NETWORK SERVER
========================================================================================================================
7.1. Intranet Architecture:
    ChevronNexus Home (Pro) transforms the user's host machine into a local media streaming and cloud storage node. This service 
    binds strictly to local intranet network interfaces (such as `127.0.0.1`, `192.168.x.x`, or `10.x.x.x`).

7.2. Zero External Routing:
    (a) Media files, video streams, audio tracks, transcoding pipelines, and shared directory assets NEVER leave your local WiFi or 
        Ethernet network.
    (b) No media metadata, file names, or streaming logs are reported to Chevron Nexus cloud infrastructure.

7.3. WiFi Monitor & Auto-Discovery:
    (a) The local network discovery subsystem utilizes standard User Datagram Protocol (UDP) broadcast packets on port 45454 to discover 
        paired NeXusWeb instances on the identical subnet.
    (b) Local device names and IP addresses enumerated during WiFi monitoring are processed in ephemeral memory and never 
        transmitted externally.

7.4. User Content Liability Disclaimer:
    The user exercises sole, exclusive legal ownership and responsibility over any files, audio-visual works, or copyrighted materials 
    stored, transcoded, or streamed via ChevronNexus Home. Chevron Nexus disclaims all liability regarding local media storage.

11. DATA SECURITY PROTOCOLS, PROCESS ISOLATION & ENCRYPTION STANDARDS
========================================================================================================================
11.1. Process Isolation & Sandboxing:
    NeXusWeb utilizes Chromium’s multi-process architecture. Web page renderers, extension scripts, and utility workers execute 
    inside restricted operating system sandboxes with minimized privileges, preventing malicious web code from reading local file 
    structures or escaping runtime isolation boundaries.

11.2. Cryptographic Security Standards:
    (a) Data at Rest: Passwords and sensitive vault elements are protected by AES-256-GCM encryption with PBKDF2 key stretching.
    (b) Data in Transit: All external network requests initiated by the browser (such as HTTPS navigation, extension downloads, 
        and sync transmissions) mandate Transport Layer Security (TLS 1.2 / TLS 1.3) with forward-secrecy cipher suites.

11.3. Local Network Boundary Protection:
    The internal IPC bridge (`tabPreload.js` / Electron context bridge) enforces rigorous context isolation, completely blocking 
    arbitrary website scripts from invoking Node.js primitives or system shell execution APIs.
